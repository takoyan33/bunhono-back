# Hono 開発ルール

このプロジェクトは Hono を利用した REST API サーバーです。
既存実装を優先し、一貫性のあるコードを書くことを目的とします。

---

# 基本方針

- 既存の実装スタイルを優先する
- 変更は最小限にする
- 不要なリファクタリングは行わない
- JSON レスポンス形式を統一する
- エラーメッセージは日本語で統一する
- HTTP ステータスコードは適切に返す
- 型安全を意識して実装する

---

# ディレクトリ構成

- エントリポイントは `index.ts`
- API の実処理は `api/app.ts`
- DB 接続は既存の接続方法を利用する
- 共通処理は必要に応じて分離する

---

# ルーティング

- REST を基本とする
- URL は複数形を使用する

例

GET /users
GET /users/:id
POST /users/add
POST /users/login
PUT /users/:id
DELETE /users/:id

---

# リクエスト

JSON は

const body = await c.req.json()

URL パラメータは

const id = c.req.param("id")

クエリは

c.req.query()

から取得する

---

# レスポンス

JSON は

return c.json(data)

文字列は

return c.text(message)

を利用する

---

# ステータスコード

200 成功

201 作成成功

204 削除成功

400 入力エラー

401 認証失敗

403 権限なし

404 見つからない

409 重複

500 サーバーエラー

---

# バリデーション

- 必須項目は最初に確認する
- バリデーションエラーなら DB にアクセスしない
- 不正な入力は 400 を返す
- エラーメッセージは利用者が理解できる内容にする

---

# エラーハンドリング

- try-catch を利用する
- 例外を握りつぶさない
- ログを残せる場合は残す
- クライアントには必要最低限の情報のみ返す

---

# 環境変数

- process.env を利用する
- 必須環境変数が無い場合は起動時に失敗させる
- ソースコードへ秘密情報を書かない

---

# 認証

- パスワードは bcrypt でハッシュ化する
- 平文保存は禁止
- ログイン時は bcrypt.compare を利用する
- password はレスポンスへ含めない

---

# コーディングルール

- async/await を利用する
- ネストは浅くする
- ガード節を優先する
- 変数名は意味の分かる名前にする
- コメントより読みやすいコードを優先する
- マジックナンバーを避ける

---

# テスト

- 成功ケース
- バリデーションエラー
- 認証エラー
- 404
- DB エラー

を確認する
